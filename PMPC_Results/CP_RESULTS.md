## 2. tau 口径对比（mode 1 / 3 / 4）

### 2.1 三种口径的定义

| 编号 | 定义 | 代码位置 | 本轮 |
|---|---|---|---|
| **1** | 常数 `M.tau_d`，各工况 case 默认：DLC `0.01` / Slalom `0.20` / FishHook `0.025` | `pmpc_core/tau_d_effective.m` else 分支 | ✅ 跑 |
| **2** | 旧纯速度表（0.017 / 0.019 / 0.022） | `tau_d_effective.m` 的 `mode==2` 分支 | ⛔ 本轮不跑（§3 有负结果） |
| **3** | **四角加权聚合**：`tau = Σ(w_i·tau_i)/Σw_i`，`w_i = |Bd_i|·|目标力−当前力|` | `prepare_step.m` + `tau_d_lookup.m` | ✅ 跑 |
| **4** | **主导角**：取 `w_i` 最大的那个角的 `tau_i` | 同上 | ✅ 跑 |

mode 3/4 的 `tau_i` 由 `pmpc_core/tau_d_lookup.m` 对
`pmpc_core/data/tau_table_tau.mat`（5×5×9 网格）做三线性插值得到，输入是
「本角当前电流 → 目标电流」和「本角压缩速度」。表由 180 组恒速电流阶跃辨识
（`MR_NLCSNN/SH_delay/tau_table_cases.csv`）经 `tau = (t90−t10)/2.1972` 换算
（`tools/build_tau_table_tau.m`；直接把 t90 当 tau 会高估 2.3 倍）。

表的量级：中位 **12.7 ms**，范围 0.5–41.4 ms；**同一速度下四条件
（压缩/复原 × 升/降电流）最大差 2.4–3.0 倍**（v=+300 mm/s：压缩升电流 19.3 ms
vs 压缩降电流 8.2 ms）。所以只看速度幅值会把方向性丢光，这也是做三维表的理由。

### 2.3 小结

- **最优：mode 1（常数）**，且只在两个大侧向工况上赢——Slalom `ey_max` 0.7433
  （比 m3/m4 好 **4.1%**）、FishHook 14.7167（好 **2.1%**）。

  0.8658–0.8660）：DLC 的减振器几乎不激励，时滞口径怎么取都看不出来。
- **最差：mode 3**——FishHook `ey_max` 15.0328（全局最差）、Slalom `SW_max` 208.7°
  （三者最大）。mode 4 与 mode 3 在 Slalom 上略有差别（SW 206.5 vs 208.7、
  `Mz_avg` 2106 vs 2115），**但在 FishHook 上两者逐拍完全相同**
  （`max|ΔD| = 6.4e-7`，四角落在同一插值格点，加权均值退化成主导角）。
- **差异最大处：Slalom 80**。`ey_max` 0.7433 → 0.7735（+4.1%），`SW_max`
  181.4° → 208.7°，`Mz_avg` 1939 → 2115 N·m，`Md_avg` 1622 → 1515 N·m。
  其次是 FishHook（`ey_max` +2.1%），DLC 可忽略。
- **mode 3 的 Slalom `ey_max = 0.7735` 与 noComp（1e-4）的 0.7735 逐位相同**：
  按辨识出的物理滞后（12.7 ms 中位）建模，闭环表现与"不补偿"没有区别。
  这是本轮最值得写进论文的一条。
  **为什么**：预测步长 `Ts = 0.1 s` 比 13 ms 大一个量级，`exp(-Ts/tau)` 只有 4.6e-4，模型里这个执行器等于"瞬时建立"。§7 的 tau 扫描给出直接证据。

### 2.4 三种口径不是同一类量

> **mode 1 的 0.20 s 是扫参得到的等效整定值（把预瞄、力界预测、离散化误差一起
> 吸收进去）；mode 3/4 的 12.7 ms 是减振器正模型阶跃辨识出来的物理时间常数
> （四条件差 2.4–3.0 倍）。两者不是同一类量，不能互相"验证"。**

因此 §2.3 的排序不能读成"常数口径更正确"，只能读成"在这个闭环里，0.20 s 这个
等效量恰好把更多的滞后一次性吃掉，收益更大"。§4 的反辨识独立支持这一点：
实测表观滞后只有 10–20 ms 量级，0.20 s 比它大一个量级。

mode 3/4 的 `tau` 不进日志（`prepare_step` 内部算完直接用于预测矩阵，`logVec`
锁死 27 列），所以这 10 个算例的 `tau_dtrace` 全为 `NaN`，`_params.mat` 里
`tau_dtrace_note = 'mode>=3: computed inside prepare_step, not logged'`。

## 4. tau_d 口径记录与反辨识（支撑 §2.4 与 §3 的结论）

> 本节用 `cp_sla_mode1` / `cp_sla_mode2` 两个 8 s 算例（§2），与 §1 的矩阵无依赖关系。

### 4.1 A 方案复盘：那次"验证"是无效的

上一轮想"从磁盘侧证 tau_d"，做法是写一个分析脚本，把
`vmag = 1000*mean(abs(vd))` 的代换表（0.017 / 0.019 / 0.022）**硬编码在脚本里**，
再对各算例的 `CmpRD_*` 套一遍，打印 `tau_d` 范围。

错在哪里：那张表是 **mode 2 的口径**。脚本对 mode 1 的算例（`.mat` 里
`tau_d=0.20`、`tau_d_mode=1`）也照样套同一张表，于是给 mode 1 的 run
打印出 `tau_d = 0.017……0.017`，看起来"验证通过"。

这不是验证，是**用结论生成证据**：脚本里预置了想看到的数值，输出当然和它一致。
真正的口径信息（这次跑的是 0.20 还是 1e-4）根本没进过数据。

### 4.2 C 方案定性：这是口径记录，不是验证

现行做法（本轮提交的代码）：`run_dlc / run_slalom / run_fishhook` 在存盘时，
用**这次运行自己的口径**（`opts` 覆盖之后的 `P.M.tau_d` 与 `P.M.tau_d_mode`）
加上**这次运行实测的**四角压缩速度 `CmpRD_*`（取自 CarSim `.vs`），
调用控制器自己的 `pmpc_core/tau_d_effective.m` 逐拍复算，存进 `.mat` 的
`tau_dtrace`（同时存 `tau_d_mode` / `tau_d_const` / `vd_ctrl`）。

> **这是口径记录（traceability），不是验证。它回答"这次用的是哪个值"，
> 不回答"这个值对不对"。**

它解决的问题是"事后能查"，而不是"证明标定正确"。上表里 mode 1 记 0.200、
mode 2 记 0.0170–0.0200，就是它给出的信息。

顺带记一条否掉的路：**不给 `.slx` 加端口回显 tau_d**。
`prepare_step.m` 里
`zeta = [meas.Vy; meas.r; meas.phi; meas.p; ey; epsi; Bd'*Fd; state.u_prev]`，
第 7 维每拍由 CarSim 实测 `Md = Bd'*Fd` 重置，**从来不在闭环里积分**；
`tau_d` 只进预测矩阵 `A(7,7) = -1/tau_d`，作用是"预测时提前多少给力"，
不留任何状态痕迹。为回显一个常数去改三份 worktree 的 `.slx`，收益为零、分叉风险为正。
另外 `pmpc_step` 的 `logVec` 是 Stateflow 数据对象，尺寸锁死 `[27 1]`，
加不了第 28 列（试过，编译直接报错）。

### 4.3 真正该做的：用 logVec 反辨识执行器时间常数

`D` 里本来就有反辨识需要的两个量（1-based 行号）：

| 行 | 含义 | 来源 |
|---|---|---|
| `D(6,:)` | `Md_actual` 实测 | `c.zeta(7) = Bd'*Fd` |
| `D(7,:)` | `Md_cmd` 本拍下发 | `stateNext.u_prev(3)`（`pmpc_step.m:160` 覆盖后的值，不是 `:68` 的上一拍初值） |

用到的两个文件：`cp_sla_mode1.mat`（= `cp_sla_80_fix`，固定 0.20）与
`cp_sla_mode2.mat`（= `cp_sla_80`，时变 17–20 ms），同一算例同一 stopTime。

一阶滞后 `dMd_actual/dt = (Md_cmd - Md_actual)/tau`，中心差分可得

```
tau(k) = (Md_cmd(k) - Md_actual(k)) / (dMd_actual/dt)(k)
```

实现：`tools/taud_backid.m`。只保留 `0 < tau < 1 s` 的样本；分母在命令平台期
接近 0，所以只统计 `|Md_cmd - Md_actual|` 超过门限的样本，并**打印门限扫描表**
——门限一动分位数就动，只报一个数等于藏证据。

**Slalom 8 s（801 拍）结果，tau [ms]，q10/25/50/75/90：**

与主 agent 的独立试算对照（mode1 49/801、中位 13.3 ms；mode2 54/801、中位 7.8 ms）：
**计数在 0.8% 门限处几乎重合（50/54 vs 49/54），中位在 1% 门限处重合（7.5 vs 7.8 ms）**；
逐点分位数的差异来自门限选择，不是算错。结论对门限不敏感：

1. **100 Hz 采样下约 10 ms 是噪声地板。** 不过滤时中位只有 1.7 / 1.8 ms，
   那是"命令与实测几乎同步"的量化假象，不是物理滞后；任何与 10 ms 同量级的
   点估计都不能当物理量读。
2. **表观滞后 ≤ 20 ms 量级，分辨不出更细。** mode2 在 0.8–1% 门限下中位 5.1–7.5 ms、
   q75 10–21 ms，被采样分辨率压住；**因此 mode2 的 17–22 ms 标定量级是对的**，
   想区分 17 / 19 / 22 三个点得把采样提到 500 Hz–1 kHz。
3. **mode1 的 0.20 s 不是执行器滞后。** 同一套被控对象，实测表观滞后中位只有
   12–34 ms（0.8–1% 门限），比 0.20 s 小一个量级；它的重尾（q90 164–208 ms）
   也说明这个数不是某个稳定时间常数。0.20 是**把预瞄（`preview_L`）、
   力界预测、离散化误差一起吸收的等效补偿量**——这也解释了为什么它比
   物理标定值 17–22 ms 大一个量级。
4. mode1 的表观滞后系统性大于 mode2（中位 12–34 vs 5–8 ms）。物理上也自洽：
   控制器假设执行器慢，就会提前给力，残余误差 `cmd-act` 被人为撑大，
   反辨识读到的滞后随之变大。

**这两个 DLC 3 s 算例不能做反辨识**：`Md` 峰值仅 ~164 N·m，1% 门限落到 ~1.6 N·m，
分子全是噪声（该门限下中位 196 / 108 ms，纯属除以小量的伪值）。反辨识只用
Slalom 这类减振器被真正激励的算例。

## 7. tau 扫描：预测步长分辨率

### 7.1 动机

`pmpc_init` 的 `M.Ts = 0.1 s`，而辨识出来的 tau 中位只有 13 ms。预测矩阵里 Md 状态
是 `A(7,7) = -1/tau`，ZOH 到 `Ts` 之后一拍的残留是 `exp(-Ts/tau)`：

| tau | `exp(-0.1/tau)` | MPC 眼里的执行器 |
|---|---|---|
| 0.013 s | 0.0005 | 一拍走完 99.95% ⇒ **等于瞬时建立** |
| 0.05 s | 0.135 | 还剩 13.5% |
| 0.20 s | 0.607 | 还剩 60.7% ⇒ 明显是慢执行器 |

所以 tau ≈ 13 ms 在 `Ts = 0.1 s` 的预测里数学上不可能产生补偿效果；
0.20 s 之所以有效，是因为它第一次让预测模型"看见"了一个明显慢的执行器。
**这不是补偿了真实滞后，是改变预测形状。**

### 7.2 扫描（Slalom 80，8 s，只改 `tau_d`，其余全部相同）

### 7.3 两个问题的回答

1. **从哪个 tau 开始 `ey_max` 才明显变化（比 `tau=0.005` 超过 1%）？**
   **`tau = 0.03 s`**（−2.40%）。0.013 s 只有 −0.07%，和 0.005 s 在噪声内不可区分；
   0.03 s 是第一个越过 1% 的点，且此后单调下降，0.05→0.3 s 之间又只再降 1.5 个百分点。
2. **这个门槛是否落在 `Ts/3` 附近（约 0.033 s）？**
   **是。** 0.03 s = `0.9 × (Ts/3)`，正好在 `Ts/3 = 0.0333 s` 附近；
   换算成残留量，门槛处 `exp(-Ts/tau) = 3.6%`。
   也就是说：**只有 tau 与 `Ts/3` 同量级或更大，预测模型才"看得见"这个滞后**；
   小于 `Ts/3` 一律被 ZOH 抹成瞬时。

### 7.4 由此得到的结论

- §2 里 "mode 3/4 与 noComp 没有区别" **不是辨识表错了**，而是 `Ts = 0.1 s`
  根本分辨不出 13 ms——预测矩阵里两种 tau 给出几乎相同的 `Ad/Bd`。
- 常见的"补偿收益"必须挂在 tau ≳ Ts/3 上才有意义；`tau = 0.20 s` 是这个闭环里
  扫出来的等效整定值（吸收预瞄、力界、离散化误差），不是物理滞后（§4 的反辨识
  给 10–20 ms）。
- 顺带一条工程结论：`SW_max` 随 tau 单调下降（206° → 167°），说明补偿在这里的
  主要作用是**减少转向修正量**，而不是把 `ey` 从 0.77 大幅拉低（最多 −4.3%）。
- 下一轮若要真正检验"补偿物理滞后"，必须先把 `Ts` 降到 τ 的量级（例如 0.02 s）
  或改 `Np/Nc`；本轮按要求没有动 `Ts`、`Np`、`Nc`。
