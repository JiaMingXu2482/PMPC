# Baseline MPC · 结果

下界基线（`baseline_mpc/`，模型 `pmpc_base.slx`）。与协调控制器的差别只在控制器本身：
被控对象、侧倾自由度、Zeng 鞍结稳定域、道路包络、`|LTR| <= 0.8` 全部同一套。
基线**不控减振器**，四角恒 `M.cdc_fixed_I = 1.0 A`；没有 Md 状态/控制量，所以没有 `tau_d` 时滞模型。
`logVec` 25 行，6–9（Md）与 14–17（Fdes）恒 NaN。

**预测时域已对齐 Proposed**：DLC / Slalom 用 `Ts=0.10 / Np=10 / Nc=5`（1.0 s 预测窗），
FishHook 用 `Ts=0.05 / Np=12 / Nc=6`。

所有数据都是 `run_baseline` 落盘：`D` 25×N、`t`、`Icmd`（四角电流，`Structure With Time`，
与 `run_dlc.m` / `pmpc_mil` 的 `Icmd_log` 同格式；`Icmd.signals.values` 是 N×4）。
每个算例另有 `<prefix>_params.mat`（字段 `meta`），记录实际生效的
maneuver / speed / horizon / Q_norm / R_norm / slack_w / cdc_fixed_I / 时间戳。

## 纵向接口（与 nc / cp 共用同一份实现）

`pmpc_base.slx` 的 CarSim 后两路输入来自和 `pmpc_mil` 的 `MPC_Controller（100Hz）`
内部**逐块一致**的速度环：

```
v_target[km/h] ── /3.6 ──┐
                         ├─ Sum(+,-) ─→ PID(PI, P=0.2, I=0.005, 输出限 ±1,
        meas.Vx ─────────┘               anti-windup = back-calculation, Kt=Kb=1)
                                          │
   pmpc_base_step 的 Tb(4) ───────────────┤
                                          ↓
                              lon_arbitrate(u_lon, Tb)
                                          │
                        throttle ─→ CARSIM_IN(10) = IMP_THROTTLE_ENGINE
                        p_brake  ─→ CARSIM_IN(11) = IMP_PCON_BK
                        u_applied ─→ Unit Delay ─→ PID 的 Tracking 口
```

- `lon_arbitrate.m` 没有复制，`run_baseline.m` / `pmpc_base_setup.m` 用
  `addpath(../pmpc_core)` 引用同一份，三边跑同一段代码。
- PID 参数与 Proposed 完全相同，没有为基线调过。
- 采样时间显式 `0.01`（`pmpc_mil` 靠外层 100 Hz 子系统继承；这里根层是 CarSim 的 1 ms）。
- `lon_arbitrate` 的规则是**稳定性优先**：DYC 激活时不额外制动、油门按斜率放开、
  油门权限不低于 0.5。差动制动期间速度本来就会被牺牲，这一条对三边同样生效。

## 鲁棒性调参（v3）

### 调参前的失效现象（v2）

| 算例 | 现象 |
|---|---|
| Slalom 80 | `LTR_max = 1.0000`（内侧轮完全卸载），`SW_max = 433.9°`，ey 0.894 |
| FishHook 80 | `LTR_max = 1.0000`，800 帧里 84 帧 \|LTR\| > 0.85，集中在 t = 1.48–3.51 s |
| DLC 80 | `SW_max = 720.0°`（机械极限），ey 1.997 m |

### 扫描 1：`slack_w(3)`（LTR 松弛权重），Slalom 80

`slack_w` 顺序是 `[r; alpha; LTR; env]`。只动第 3 项，其余保持 case 默认。

| `slack_w(3)` | LTR_max | ey_max | SW_max [°] |
|---|---|---|---|
| 5（原值） | 1.0000 | 0.8936 | 433.93 |
| 50 | 1.0000 | 0.7458 | 191.17 |
| 200 | 1.0000 | 0.7581 | 139.41 |
| **1e3（采用）** | **0.8282** | **0.8336** | **138.38** |
| 1e4 | 0.8282 | 0.8336 | 138.52 |

拐点在 200 与 1e3 之间；1e3 与 1e4 结果一致（约束已等效为硬约束），
所以取**满足 LTR < 0.85 的最小值 1e3**。ey 不但没退化，还比原值好 6.7%。

### 扫描 2：`slack_w(3)`，FishHook 80

| `slack_w(3)` | LTR_max | ey_max | Mz_max |
|---|---|---|---|
| 1e4（原值） | 1.0000 | 10.18 | 5335 |
| 1e5 | 1.0000 | 11.87 | — |
| 1e6 | 1.0000 | 12.21 | — |

**零敏感**。继续按 (c) 抬 `slack_w(1)(2)`（横摆 / 侧偏松弛，让 QP 优先保 LTR）：

| `slack_w` | LTR_max | φ_max [°] | Mz_max |
|---|---|---|---|
| `[1e3 1e3 1e6 1e-3]` | 1.0000 | 7.67 | 5493 |
| `[1e4 1e4 1e6 1e-3]` | 1.0000 | 7.68 | 5032 |

最后按 (d) 动 `Q_norm(3)`（侧倾角权重，原值 20）：

| `Q_norm(3)` | LTR_max | φ_max [°] | Mz_max |
|---|---|---|---|
| 100 | 1.0000 | 7.54 | 5355 |
| 400 | 1.0000 | 6.03 | 6954 |

侧倾角被明显压下去了（7.67° → 6.03°），**但 LTR 仍然是 1.0000**。
结论见下面的「FishHook 为什么压不住」。**FishHook 的参数全部保持原值**——既然
改了也达不到目标，就不动它。

### 扫描 3：DLC 80 的 `SW_max`

先试 `slack_w(3)`：

| `slack_w(3)` | LTR_max | ey_max | SW_max [°] |
|---|---|---|---|
| 2000（原值） | 0.3378 | 1.9966 | 720.00 |
| 1e4 | 0.3378 | 1.9966 | 720.00 |
| 1e5 | 0.3378 | 1.9966 | 720.00 |

**完全无效**：DLC 的 LTR 只有 0.34，`|LTR| <= 0.8` 这条约束从来没激活过，
调它的松弛权重什么也不会发生。方向的病根是方向盘被"越差越打"的正反馈顶到限位，
所以改 `R_norm(1)`（dDelta 增量代价）：

| `R_norm(1)` | ey_max | SW_max [°] | LTR_max |
|---|---|---|---|
| 100（原值） | 1.9966 | 720.00 | 0.3378 |
| **300（采用）** | **0.8753** | **228.42** | 0.3345 |
| 1000 | 0.8974 | 138.03 | 0.3366 |

300 与 1000 都满足 `SW <= 400°`；取 300——离原值更近，且 ey 略好。

### 最终采用值

| 工况 | 改动 | 理由 |
|---|---|---|
| DLC | `R_norm = [300; 200]`（原 `[100; 200]`） | SLACK 对 SW 无效，只能从方向增量代价下手；300 时 SW 720°→228° |
| Slalom | `slack_w = [5; 5; 1e3; 5]`（原 `[5; 5; 5; 5]`） | LTR 1.000→0.828；1e4 与 1e3 等价，取小值 |
| FishHook | 不变 | 所有可调项（LTR/横摆/侧偏松弛、侧倾权重）都压不住，见下 |

### 代价：为了不翻车，ey 退化了多少

**没有退化，全部变好**（v2 → v3）：

| 算例 | ey_max v2 → v3 | 变化 | SW_max v2 → v3 |
|---|---|---|---|
| DLC 70 | 0.6178 → **0.6028** | −2.4% | 71.27 → 58.12 |
| DLC 75 | 0.7604 → **0.6457** | −15.1% | 268.78 → 93.78 |
| DLC 80 | 1.9966 → **0.8753** | −56.2% | 720.00 → 228.42 |
| Slalom 80 | 0.8936 → **0.8336** | −6.7% | 433.93 → 138.38 |
| FishHook 80 | —（无路径跟踪） | — | 0 → 0 |

原因：原参数让车"越偏越打方向"直到限位，反而把路径跟踪彻底搞坏。
把方向增量代价和 LTR 松弛提上来之后，车是在可控范围内走的，`ey` 反而小了。

### FishHook 为什么压不住（结论，供 MAIN 决策）

`LTR_max = 1.0` 是**两个瞬时的轮离地**（t ≈ 1.5 s 与 3.2 s），不是持续翻车；
4 s 之后 LTR 稳定在 0.65–0.79。原因不在权重，在两点：

1. **约束用的是一个准静态 LTR 模型，缺滚转阻尼项。**
   `pmpc_base_prepare.m` 里 `Hr = kL*(kg*ay + [0 0 V.Kt 0 0 0])`——`ay` 与 `phi`（弹簧）有，
   但 `p`（滚转角速度）那一列是 0。滚转瞬态时减振器产生的载荷转移完全没建模。
   按模型算，φ=6.2° 时 LTR ≈ 0.77 < 0.8，QP 认为还安全；实车已经 1.0。
   所以 `slack_w(3)` 从 1e4 加到 1e6 一个数都不变——约束**从来没被违反过**，罚不罚都没区别。
   （同一个 `Hr` 也在 `pmpc_core/prepare_step.m` 里，是三方共用的口径，不能单方面改。）
2. **FishHook 下基线没有任何转向权限**：`M.afs_on = false, steer_ext = true`，
   方向盘由 CarSim 开环机器人给，`SW ≡ 0`；唯一能用的执行器是差动制动，
   而轮离地那一刻轮胎已接近饱和（`brakeMax` 由 `(mu*Fz)² - Fy²` 决定，趋于 0）。

如果要真的把这 84 帧压下去，可选做法（都不在"只调权重"范围内）：
(a) 给 `Hr` 加滚转阻尼项 `-c_phi*p`，但这是三方共用的约束模型，需要 MAIN 同意后三边一起改；
(b) 让基线在 FishHook 下也有转向权限（`afs_on = true`），但那等于改变工况定义。
