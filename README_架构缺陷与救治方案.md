## 零、一句话结论

**物理和实验结果是好的，坏的是数学结构与论文叙事对不上。**
三条 A 级缺陷互相咬合：优先级不是真优先级、协调在展示工况里没被激活、
效果主要来自削转角。三条加起来等于核心贡献缺乏实验支撑。
但每条都有明确的补法，见第三节。

## 一、先澄清一条：AFS 削转角没有想象中严重

实测 AFS 有 51.7% 的时间顶在 ±97.4°(方向盘)，把驾驶员 294° 的输入削到 196.6°。

但：

```
97.4° / 17 (转向比) = 5.73° = 0.1 rad = Wang 2023 用的 δ_fm
294° - 196.6° = 97.4°  <- 正好等于限幅值
```

即控制器**用满了文献标准的 AFS 权限**，不是任性地拒绝打方向。
这条从「漏洞」降级为「需要量化说明的现象」——只需补算因此产生的横向位移偏差。
若车辆仍在车道内，此项不构成问题。

## 二、缺陷清单

### A 级 —— 动摇论文主张

#### A1. σ 优先级机制名不副实

**是什么**：标题写 "Priority-Based"，但 σ 不是决策变量。

**证据**（结构）：γ 在整个 QP 里只出现在 `func_BuildQPConstraints.m:102-118`
的 `umin·γ ≤ u(k) ≤ umax·γ`，其余每条约束的 γ 列都是 `zeros(·,Nr)`，
系统方程里没有 γ。代价里只有单调递增的 `Nc·V·γ²` 加迟滞项
`W_dgamma·(γ-γ_prev)²`，而 `CostWeights.Wdg = [0 0 0]`——迟滞项是关的。
故最优解有闭式：

```
γ* = clip( max( max_{k≤Nc} |u(k)|/u_max , ρ_min ), 0, ρ_max )
```

**证据**（数值，鱼钩 PMPC 800 拍）：`MFxmax>300` 时
`corr(ρ_DB, |u|/umax) = 0.986`，83.1% 的拍 `|gap| < 1e-2`。
ρ_AFS 分布双峰：<1e-3 占 31.1%、>0.999 占 50.1%、中间仅 18.8%。
ρ_CDC 被 `rho_min=[0;0;1]` 钉死，98.2% 的时间 >0.999，
所以 `Nc·V3·γ²` 是常数——**V3 从 10 扫到 8e4 无任何响应，至此有确切解释**。

**为什么要命**：审稿人推一遍 KKT 就能看出来。

**注**：V1/V2/V3 并非无用。消去 γ 后等价于对归一化执行器用量的
峰值(L∞)惩罚，γ 是其 epigraph 变量。机制是真的，**名字是错的**。

#### A2. 鱼钩工况下上层 MPC 退化为侧倾调节器

`cq32019mpc.m:125-130`：`Q1=Q2=Q5=Q6=0`，只剩 `Q3=2e4`(侧倾角)、`Q4=2e3`(侧倾角速度)。
即在用来展示效果的工况里，多目标协调根本没被激活——无横摆跟踪、无路径、无侧偏。
DLC 工况有协调但那是另一套权重。

**没有任何一个工况同时检验了「协调」与「优先级」。**

#### ~~A3. 不侧翻主要靠不打方向~~ **2026-09-05 基本推翻，见任务 #9**

见第一节的澄清（AFS 用满的是文献标准权限 δ_fm）。
任务 #9 用 AFS 权限扫描直接量化后，**原判断与数据相反** —— 详见下文。
残留的一条：鱼钩模式 `Q5=Q6=0` 且无 `ey` 约束，没有机制限制路径偏差；
但鱼钩本身没有目标路径，该问题只在任务 #8 的联合工况里才真正成立。

#### A4. DLC 闭环对数值无关的扰动极度敏感（2026-08-31 发现）

**是什么**：DLC 工况的结果不可靠 —— 任何**数学上证明不影响最优解**的改动，
都会让结果变化两三倍。

**证据**：在 `rho_min=[0;0;1]`（γ_CDC 被钉在 1）的代码上，`Nc·V3·γ_CDC²`
是一个常数，**不可能影响 argmin**。只改 V3 一个数：

| V3 | 路径误差RMS m | 侧倾峰 deg | 抬轮 % | 制动峰 N·m | MR力峰 N |
|---|---|---|---|---|---|
| 1 | 0.9235 | 4.010 | 5.56 | 244.4 | 1904 |
| 5 | — | 3.542 | 4.00 | 577.0 | 1525 |
| **9.5** | — | **4.045** | **5.56** | 238.0 | 1675 |
| **10** | **0.2665** | **2.684** | **0.00** | 318.0 | 1064 |
| 20 | — | 3.237 | 0.00 | 129.1 | 1631 |

V3 从 9.5 改到 10（惰性项变化 5%）→ 侧倾峰 4.045→2.684 deg（−34%）、
抬轮 5.56%→0%。这不是趋势，是散点。

**不是不确定性**：同一份代码重跑逐位相同（`dlc_repro` vs `dlc_after`
最大差 **0**）。是确定性的混沌敏感 —— 对初值/舍入的敏感依赖。

**为什么鱼钩没事**：鱼钩是 Add 模式，驾驶员 294° 的输入主导轨迹，
AFS 只叠加 ±5.73°，闭环大部分由外部激励决定，所以 V3 扫描给出的是
光滑单调的趋势（制动占空 71.9→74.7→73.4→86.3→97.2）。
**DLC 是 Replace 模式，MPC 独自操舵**，路径跟踪闭环完全自持，
在 100 km/h / μ=0.9 / a_y≈0.75 g 这个点上处于临界稳定附近。

**后果**（严重）：
1. 论文里任何**单次** DLC 结果都不可信，包括任务 #1 测到的
   「路径误差 −7.8%」—— 那个改善量落在散点带内，可能是噪声；
2. 审稿人复现会得到不同的数；
3. 跨工况权重迁移的验证（救治 2）在 DLC 上无法立足。

**待查方向**：QP 是否退化/热启动路径依赖（`无解` 每次 1~3 次，
`收敛` 计数也在 0~5 跳）；AFS 速率限 20°/s 是否过紧导致极限环；
100 km/h 是否已越过该车+该控制器的可跟踪边界。

**候选对策**：
1. **降低 DLC 严酷度**（如 80~90 km/h），让工作点离临界远一些；
2. **集合报告**：对 N 次带微扰的运行报均值±离散度，而不是单次曲线
   （诚实且是标准做法，但掩盖不了闭环临界的事实）；
3. 定位并消除敏感源（QP 退化 / 速率限 / 权重）——这是真正的解法。

### B 级 —— 审稿人大概率会抓

#### B1. 归一化层混用两类分母，权重不能跨工况

`Q` 系列除以「限值」（常量）——正确。
`R2` 除以「瞬时可达值」`MFxmax`——错误。抬轮时 `MFxmax=0` → `R2=Inf` →
H 非有限 → QP 失败，曾 799 次求解崩 137 次（17%）。现靠地板
`max(dMFxmax²,1e3)` 续命，未根治。

正好撞在 Wang 2023 批评 MPC 的原话上（"难以仅靠调权重系数适应不同工况"）。

#### B2. 所有约束都是软的，且松弛无上界

`func_BuildQPConstraints.m:148`：`eps_ub = inf(Ne,1)`。
LTR 约束、侧偏角约束全软，满足与否取决于权重大小。
加上**没有终端代价、没有终端集**（已确认 `func_BuildQPCost.m` /
`func_SystemFurture.m` 中无相关项），故既无防侧翻保证，也无递归可行性与稳定性证明。

#### B3. 下层四角分配规则是类比来的

MR 按 Vx 分配是从差动制动按 Fz 分配「联想」过来的，无论证。

## 三、救治方案

### 救治 1：让 σ 真正成为决策变量（对应 A1、C2、C3）

σ 是从属量的根因是「只出现在一处约束」。让它在别处也出现即可。
以下三条改动都保持约束对 γ 的仿射性，不动求解器。

**1A — 加物理耦合预算**

```
σ_AFS + σ_DB ≤ B(t)
```

依据不是人为设定：AFS 消耗前轴**侧向**摩擦、DB 消耗**纵向**摩擦，
两者共享摩擦圆，B 由当前附着裕度算出。加上这一行后 AFS 要多用则 DB 必须让位，
**这才是优先级分配**。
改动位置：`func_BuildQPConstraints.m` 增加一行 `A_cons`。

**1B — 重新定义 σ_MR（同时解决 C2 与 V3 无响应）**

MR 常开是物理事实（半主动件退不出），但常开不等于不能定价——可退的是**调制幅度**：

```
Md_0 − σ·(Md_0 − Md_min)  ≤  u_MR  ≤  Md_0 + σ·(Md_max − Md_0)
```

`Md_0` = 2.0 A 被动工作点对应的力矩。
σ=0 → 保持被动阻尼不动；σ=1 → 用满调制范围。对 γ 仍是仿射，约束结构不变。
收益：
- σ_MR 成为真变量，V3 有意义
- 物理建模正确（这才是半主动阻尼器的正确写法）
- baseline（固定 2.0 A）= σ_MR ≡ 0 的特例，对照关系变干净

**1C — 打开 `Wdg`**（1 行，`cq32019mpc.m:134`）
给 σ 加记忆，消掉 ρ_AFS 的 bang-bang 行为，正面支撑「连续 vs Wang 离散切换」的卖点。

### 救治 2：设计能同时激活两个目标的工况（对应 A2）

空载 DLC 与载货 DLC **不是同一件事**：

| 工况 | 路径跟踪 | 防侧翻 | 有无权衡 |
|---|---|---|---|
| 空载 DLC 100 km/h | 主导 | 不激活 | 无 |
| 鱼钩 载 170 kg | 不激活 | 主导 | 无 |
| **载货 DLC 提速至临界** | 激活 | 激活 | **有** |

前两个各自只激活一半目标，所以「协调」从未被检验。
载货 DLC 逐步提速直到控制器必须在路径误差与 LTR 之间取舍——**那个取舍点才是实验证据**。
不是重复，是唯一能同时打开两个目标的工况。且 Wang 2023 的验证工况正是
slalom + DLC + fishhook，可正面对齐。

备选（更新颖、工作量更大）：DLC 中途遇对开路面（μ-split），
横摆扰动 + 路径 + 侧倾三者同时激活。

### 救治 3：归一化换常量参考值（对应 B1）

原则：**约束负责说「此刻能做到什么」，归一化负责说「我们在意的尺度是多少」。**
两者混用即重复计入。

- `R2` 分母：`(MFxmax·Ts/0.2)²` → `((tf/(2·rt))·Tb_max·Ts/0.2)²`（额定制动力矩，常量）
- `Q2` 分母：`r_ssmax²` → 常量 `r_ref = μ·g/V_nom`
  （`r_ssmax` 继续留作**约束限值**，那里用是对的）
- `S2`/`S3` 同理（当前 S 全为 0，暂不咬人，但公式要一致）

改完后地板补丁 `max(dMFxmax²,1e3)` 可拆除。
改动位置：`func_CostWeightingRegulation_QuadSlacks.m` 第 155–180 行附近。

### 救治 4：松弛变量有限化（对应 B2）

`eps_ub = inf` → 有限值（如 LTR 松弛上限 0.05）。**1 行**，
换来「约束违反有上界」这句可写进论文的话，并报告实测最大违反量。
完整稳定性证明成本过高，本轮不做，在 limitation 中坦白。

### 救治 5：必须修的 bug（对应 C1）

`Fy0` 在 DLC 分支补上 `cb_f·delta_f`。修完必须重跑 DLC，
且 `dlt_rate_max` 与 `R1` 需重新确认。

### 无法廉价解决、拟在 limitation 中坦白

- B3 下层四角分配规则的最优性论证
- B2 的完整稳定性/递归可行性证明

### 2026-08-31 — 任务 #1：修正 `Fy0`

**文件**：`cq32019mpc.m`（原文件备份在 scratchpad `cq32019mpc_before_Fy0fix.m`）

**改了什么**：删掉 `Fy0` 的工况分支，两个工况统一为

```matlab
Fy0 = fb_f + cb_f*(VehStateMeasured.delta_f - delta_robot);
```

**为什么**：由 `func_DynamicalModel.m:53` 的预测式反推

```
Fyf(u) = CbF*(vy+lf*r)/vx - CbF*u + F_off_f_eff
(vy+lf*r)/vx = ab_f + delta_f
F_off_f_eff  = fb_f - cb_f*ab_f - cb_f*delta_robot
=> Fyf(u) = fb_f + cb_f*(delta_f - delta_robot) - cb_f*u
```

`u=0` 时即上式，与原鱼钩分支一致。原 DLC 分支写成
`cb_f*(ab_f - delta_robot) + F_off_f`，用 `ab_f` 顶替了 `(ab_f + delta_f)`，
漏掉 `cb_f*delta_f`。

**影响面**：`Fy0` 只用于转角界 `dlt_ub/dlt_lb = (±Flim - Fy0)/|cb_f|`。
量纲上偏差 = `cb_f*delta_f/|cb_f| ≈ delta_f`，DLC 中约 6~11°，
而 `dlt_mec = 20°`——即每一拍都按「当前转角为零」去算力限，
转角界整体偏移，约束未失效但明显偏心。

**回归验证**：鱼钩分支式子逐字未变，重跑 FH_PMPC，
`all` 变量 800×31 共 24800 点最大绝对差 **0**，逐位相同。
求解 792 次 / 无解 3 / NaN 0。脚本：`regress_fh.m`

**DLC 前后对比暴露出第二个、更严重的缺陷** —— 见下一条。

|---|---|---|---|---|---|
| 4.51 | −1715 | −78562 | **+10694** | −0.243 | 0.81（`dlt_ub` 被钳到 0）|
| 5.31 | −8618 | **0** | −8618 | **0** | 0.22 |
| 6.01 | −8299 | **0** | −8299 | **0** | 0.000 |

**根因**：`dlt_ub = (Flim − Fy0)/Cm` 把切线轮胎模型**外推到 u=0**，而 `Fy0` 是幻觉力
——真实轮胎会饱和，线性外推却给出 ±10 kN 这种超过 `Flim` 的值。于是 `dlt_ub<0`
或 `dlt_lb>0`，**箱体变成单边**，AFS 只能往一个方向打。
实测 `dlt_ub==0` 占 6.3%、`dlt_lb==0` 占 27.6%。
前轮完全饱和后 `cb_f` 精确归零，`Cm` 退到 5e3 的地板、`|fb_f|` 又略超 `Flim`
（`Flim = 0.95·μ·Fzf` 只是估计值，轮胎表自己的峰值可以更高），
`dlt_lb` 就永久卡在 0 —— 自持陷阱，AFS 再也回不来。

旧代码之所以没暴露，是因为 `Fy0 = fb_f` 恰好被摩擦圆限住，从没越界。
**即 C1 不是一个算术笔误，而是「把切线外推到远离工作点」这个建模错误。**

**改法**：以当前工作点 `u_op = delta_f − delta_robot` 为中心表达余量，不外推：

```matlab
u_op    = VehStateMeasured.delta_f - delta_robot;
head_up = max(Flim - fb_f, 0)/Cm;
head_dn = max(Flim + fb_f, 0)/Cm;
dlt_ub  = min( dlt_mec, u_op + head_up);
dlt_lb  = max(-dlt_mec, u_op - head_dn);
dlt_ub  = max(dlt_ub, 0);   % gamma->0 要能退到 u=0
dlt_lb  = min(dlt_lb, 0);   % 且"不打方向"绝不违反摩擦极限
```

余量取 `max(·,0)` 保证箱体恒含当前转角；`cb_f→0`（轮胎饱和）时余量发散，
力限自动退出、只剩机械限 —— 饱和时切线模型本就说不出话。
`Fy0` 随之成为死变量，已删除，注释改写为以工作点为中心的推导。

### 2026-08-31 — 任务 #2：σ_MR 重定义为「调制幅度」

**动机**：`rho_min=[0;0;1]` 把 γ_CDC 钉在 1，`Nc·V3·γ²` 退化为常数，
V3 从 10 扫到 8e4 各项指标逐位相同（见 [README_归一化审查.md](README_归一化审查.md) 第四节）。
但 MR 常开本身是对的 —— 半主动件断电仍出力。错的是把这个物理事实
写成了 `rho_min`，而不是写进 γ 的定义。

**改法**：把优先级约束的中心从 0 挪到各执行器的「零作用点」`uc`：

```
uc + γ·(umin − uc)  ≤  u(k)  ≤  uc + γ·(umax − uc),    uc = [0; 0; Mdnom]
```

- AFS / DB 是主动件，不作用即 `u=0`，`uc=0`，**完全退化为原式**；
- MR 的 `uc = Mdnom` = 标称电流 `I_nom` 下四角阻尼力产生的侧倾力矩。
  `γ_CDC=0` → 保持被动阻尼（物理正确、始终可行）；`γ_CDC=1` → 用满调制范围。
- `rho_min` 放回 `[0;0;0]`。
- baseline（固定 `I_nom`）= `γ_CDC ≡ 0` 的特例，对照关系变干净。

### 2026-08-31 — 缺陷 A4 定位：QP 病态 (cond = 1.04e13)

**查法**：给 `func_SolveMPCQP.m` 临时插桩，逐拍记录 exitflag / 迭代数 /
`cond(H)` / `diag(H)` / `‖f‖`。H 只有 29×29（`Nu·Nc+Ne+Nr = 18+8+3`），代价很低。

**结果**：`cond(H) = 1.04e13`，**每一拍都一样**（中位=p95=最大），
说明由固定的权重尺度支配，与状态无关。`diag(H)` 分段量级：

| 段 | diag(H) |
|---|---|
| ΔU — AFS | 4.16e5 ~ 3.72e6 |
| ΔU — DB | 2948 |
| **ΔU — MR** | **3.97e−05** |
| 松弛 ε（横摆/侧偏） | 1.38e6 |
| 松弛 ε（LTR） | 4.0e7 |
| 松弛 ε（位置） | **1.5e8** |
| γ (AFS/DB/MR) | 1200 / 9.6e5 / 12 |

跨度 **3.78e12**。MR 的增量权重比位置松弛权重小 12.6 个数量级 ——
双精度 `eps = 2.2e-16`，`cond = 1e13` 下病态方向只剩约 3 位有效数字，
`OptimalityTolerance = 1e-6` 形同虚设，active-set 落到哪个顶点取决于舍入。
**这就是「数学上惰性的改动也能让闭环变化两三倍」的机制。**

来源正是 B1（归一化混用两类分母）与 C4（`R2=1e9`、`W4=5e7` 没有物理来源）。

**已做的处置：Jacobi 预缩放**（`func_SolveMPCQP.m`）

```matlab
dH  = max(diag(H), eps*max(diag(H)));
sc  = 1 ./ sqrt(dH);
Hs  = (sc*sc.') .* H;   fs = sc .* f;   As = A_cons .* sc.';
lbs = lb ./ sc;  ubs = ub ./ sc;  x0s = WarmStart ./ sc;
[xs,~,exitflag] = quadprog(Hs, fs, As, b_cons, [], [], lbs, ubs, x0s, options);
x_opt = sc .* xs;
```

`S` 是正定对角阵，这是同一个问题的等价改写，只改求解器看到的数值尺度。

| | 原 | 缩放后 |
|---|---|---|
| `cond` | 1.04e13 | **45.6**（最大 170）|
| `‖f‖` | 8.53e8 | 7.06e4 |
| 迭代数中位 / p95 | 30 / 58 | 27 / 45 |

1. **散度大幅下降但未消除**（ey_RMS 仍有 19.6% 变异）。剩余部分要么是

### 归一化修好之后暴露的问题：权重数字差 9 个数量级

分母统一之后，`CostWeights.*` 的数字有了统一含义 ——
**「该项用满其参考量时的代价」**，因此现在可以直接横向比较：

| 组 | 归一化空间中的数值 |
|---|---|
| Q（DLC） | Q3=1e2, Q5=2e3, Q6=2e2 |
| Q（鱼钩） | Q3=2e4, Q4=2e3 |
| **R** | **R1=1, R2=1e9, R3=5** |
| W | W1=W2=5e4, W3=5e6, W4=5e7 |
| V | V1=100, V2=8e4, V3=1 |

`R1 : R2 : R3 = 1 : 1e9 : 5` —— 三者都是「用满该执行器每拍速率能力的比例的平方」，
本应是可比的数量级，实际差 9 个数量级：**差动制动的增量被罚得比 AFS 重十亿倍。**

原注释写着「R2 归一化后 =1e9/dMFxmax² ~ 640, 与 Q5(7054) 同量级」——
作者是拿**未归一化**的有效值去和 Q5 的有效值对齐的，那是在两个不同的变量空间里比较，
正是归一化本该杜绝的错误。

**结论**：这些数字原本是为了补偿错误的归一化才那样取的。现在归一化对了，
它们必须在归一化空间里重选。这就是任务 #3b，且现在才第一次有意义。

**注意区分两件事**：
- **归一化**修好的是权重的**含义**（可比、可迁移、不随状态漂移）；
- **Jacobi 缩放**修好的是**数值条件**（`cond` 1e13→46）。
  即使权重含义正确，AFS 用 rad、DB/MR 用 N·m，`diag(H)` 天然跨多个数量级，
  所以 Jacobi 缩放要一直留着。

**鱼钩验证见下一条** —— 归一化修好后第一次能有意义地扫权重，结果很大。

### 2026-09-01 — 核 `Md_rate_per_sec` 的物理来源

原值 `Constraints.Md_rate_per_sec = 500/0.03`，读作「500 N·m 在 30 ms 内完成」。
查下来三个问题：

**① `500 N·m` 没有任何来源。** MR 能调制的侧倾力矩幅度在任务 #6 已经算过：
`Md_ref = 0.5(d_f+d_r)·[Gu(V_d)−Gl(V_d)] = 2328 N·m`。原值只有它的 21%。

**② `30 ms` 也不来自自有数据。** 本项目的 MR 实测（`试验\MR减振器`、`试验\MR1219`）
全部是正弦激励的 F-V / F-X 特性试验：行程 100 mm、5 个速度
（0.052 / 0.131 / 0.262 / 0.524 / 1.04 m/s）、电流 0~2.5 A、每次 5 个循环、
外筒温度 28~33 °C。**没有阶跃电流响应测试**，辨识出的 `func_hybrid_MR_model`
也是准静态 `F(v, I)`（`beta0` 是形状参数，不是时间常数）。
所以响应时间无法从自有数据标定，30 ms 只能是规格书典型值（MR 阻尼器一般
10~25 ms），取偏保守。**要坐实它，需补一次「定速激励 + 阶跃电流」的响应时间测试。**

**③ `Ts` 与 `Ts_exec` 有一处 5 倍不对称。** AFS 的速率界按 `Ts_exec = 0.01` 缩放，
MR 却按 `Ts = 0.05`。同一种「每预测步增量上限」，两个执行器差 5 倍且无依据。

**改法**

```matlab
% cq32019mpc.m
Constraints.tau_MR = 0.03;                    % s, MR 力响应时间(规格书典型值)
% func_CostWeightingRegulation_QuadSlacks.m
dMdmax = (Md_ref / Constraints.tau_MR) * Ts_r;   % Ts_r 与 dFyfmax 同源
```

**两处修正几乎抵消**：`2328/0.03 × 0.01 = 776` vs 原 `(500/0.03) × 0.05 = 833`，
差 7%。实测 DLC 各项变化都在 3% 以内（路径误差 RMS +0.1%），
即**行为不变，但推导从魔数变成了从阻尼器模型算出来的量**。

### 新发现的待办：ΔU 的速率界用错了时间步

`Ts = 0.05`（预测模型步长）而 `Ts_exec = 0.01`（S-function 触发周期）。
QP 的决策量 `ΔU(k), k=1..Nc` 是**预测步**上的增量，预测模型每步推进 0.05 s；
但只有 `ΔU(1)` 被真正施加，且只作用 0.01 s 就重新求解。

现在两个都按 `rate·Ts_exec` 限，后果：

- `ΔU(1)`：**正确** —— 施加的物理滑移率恰好等于 rate；
- `ΔU(2..Nc)`：**过紧 5 倍** —— MPC 以为自己的执行器在时域内比实际慢 5 倍。

量化（AFS，`rate = 42.35 deg/s`，`Nc = 6`）：预测跨度 `6×0.05 = 0.3 s`，
物理上前轮可以走 `42.35×0.3 = 12.7 deg`，而 QP 只允许 `6×0.42 = 2.5 deg`。

> **⚠ 这一段的推论后来被实测证伪，见下方「2026-09-01 —— 速率界分段：两种改法都更差」。
> 保留原文以记录推理过程。**

分段速率界（`ΔU(1) ≤ rate·Ts_exec`、`ΔU(k≥2) ≤ rate·Ts`）能同时满足两边，
但会把约束写得很杂。**用户 2026-09-01 决定：不做分段**，保持统一的
`rate·Ts_exec`。记录在此，避免以后重复提议。

方案 (x) 还有一处自身的毛病：`ΔU(1)` 紧、`ΔU(k≥2)` 松，规划出的轨迹是
「前 50 ms 几乎冻结、之后突然快跑」的折线，现实中不对应任何东西。

**决定：保持 (c)，全部按 `Ts_exec` 限。** 已在
`func_CostWeightingRegulation_QuadSlacks.m` 的 `dFyfmax` 处留下结论注释，防止重复踩。

（`x0s = min(max(x0s, lbs), ubs)`），省一次 active-set 的 Phase-1，无害。

**方法论备注**：这条与 `R2=1e9`、`dlt_rate_max=20` 不同 ——
那两个是「把对象属性当权重调」的确凿错误，而这一条是**看似不自洽、实则被滚动时域
补偿掉的建模保守性**。判据只能是实测：三个方案都跑一遍，看物理量。

#### 为什么两个工况方向相反（机理）

方案三把节点 2..Np 锚在**预测的状态**上，成败取决于名义轨迹准不准：

- **DLC**：MPC 独自操舵，热启动的名义轨迹基本就是它自己要执行的 → α 准 → 得益；
- **鱼钩**：驾驶员独立注入 294°，与 MPC 的计划无关 → 名义轨迹失准 → 反受其害。

**鱼钩失准的确切来源**：`delta_robot` 在整个预测时域内**按常值保持**。
鱼钩转向机器人以 720 deg/s 运动，时域长 `Np·Ts = 0.6 s`：

```
720 deg/s × 0.6 s = 432 deg  的驾驶员转角完全没进预测模型
```

每个节点的 α 都建立在「驾驶员不再动方向盘」这个错误假设上。
Ataei 2020 也是这么做的（原文 "the driver's steering angle is assumed constant
during the prediction horizon"），在他的工况下或许无妨，在 720 deg/s 的鱼钩里是致命的。

**下一步**：用实测 `δ̇_robot` 把驾驶员转角外推到各节点，再重测鱼钩。
这一条同时也是方案二的隐含假设，值得单独作为一个论点。

### 2026-09-01 — 任务 #4：σ 耦合，两种做法都试了，都不采纳

目标是让 γ 不再各自独立地被 `|u|/umax` 顶上去，而是必须互相让位。
先做了一个前置检查 —— **这个约束会不会真的咬住**：

| 数据集 | σ_AFS+σ_DB 均值 | 中位 | 最大 | >√2 占比 |
|---|---|---|---|---|
| 鱼钩 | 1.368 | 1.423 | 2.000 | **50.1%** |
| DLC | 0.410 | 0.269 | 1.746 | 2.6% |

会咬住，而且只在鱼钩。于是两种做法都实现并实测。

#### 方案 A：σ 预算 `σ_AFS + σ_DB ≤ B`

依据本想取摩擦椭圆 `a²+d²≤1` 的切线线性化 `B=√2`。
**但这个依据在预算真正咬住的工况里不成立**：鱼钩下 `dlt_mec = AFS_max = 5.73°`
（Wang 的 δ_fm）几乎总比力限更紧 —— 证据是方向盘峰值恒为
`294 − 196.59 = 97.41° = 5.73×17`，精确顶在作动器幅值限上。
所以那里 σ_AFS 度量的是「作动器行程用了多少」，不是「侧向摩擦用了多少」。

实测（鱼钩）：

| B | 时长 s | 侧倾峰 deg | \|LTR\|>0.99 % | 抬轮 % | 制动峰 N·m | MR力 RMS N |
|---|---|---|---|---|---|---|
| 0（关） | 7.975 | **4.982** | **0.31** | **4.06** | 2490 | 376 |
| 1.414 | 7.975 | 7.345 | 9.69 | 10.62 | 1470 | 502 |
| 1.2 | **3.475** | **76.8** ⚠侧翻 | 48.6 | 60.0 | 630 | 751 |
| 1.0 | **2.975** | **79.07** ⚠侧翻 | 40.0 | 56.7 | 301 | 825 |

预算确实咬住（σ 和的最大值精确等于 B），**机制有效但决策方向错误**：
制动峰 2490→301 被饿死，MR 力 RMS 376→825 拼命补，MR 一个人挡不住侧翻。

**机理**：紧急工况需要所有执行器同时满负荷，不是配额制。而且 AFS 受机械限、
DB 受摩擦限，两者本就不共享资源，强行竞争等于凭空削弱控制器。

#### 方案 B：前轴摩擦耦合（力层面，物理正确）

`MFxmax` 用**实测** `Fy` 算摩擦余量 `Fx_u = sqrt((μFz)²−Fy²)`，
漏掉了 AFS 打算改变 `Fyf` 这一项。一阶修正：

```
|u_DB| + κ·|u_AFS − u_op| ≤ 0.95·MFxmax
κ = (tf/2)·(|Fy_f|/Fx_u,f)·|c̄_f|/2
```

绝对值形式（菱形）是保守内近似，展开为 4 行/步；
`u_AFS = u_op` 时退化为原约束，故 `ΔU=0` 始终可行。
4 行展开与绝对值形式的等价性做了 200 组随机数值校验，全部通过。

实测（鱼钩）：**全部指标变化 <0.5%，完全惰性。**

**原因**：κ ≈ 1.8e4，时域内 `u_AFS` 最多移动 `Nc·dFyfmax = 0.044 rad`，
削减量约 790 N·m；而 `0.95·MFxmax ≈ 6100 N·m`，实测制动峰只有 2490 ——
**差动制动全程只用到摩擦能力的约三分之一，约束够不着**。
DLC 侧制动峰 2293、占空 16%，比例更低，只会更惰性。

#### 结论

两个开关默认 0（`Constraints.sigma_budget`、`Constraints.fx_couple`），代码保留。

**σ 仍是 epigraph 从属量，论文措辞按 README_归一化审查 4.3 / 4.5 如实写。**
这不是失败的探索：它排除了「加耦合约束就能让 σ 成为真决策变量」这条路，
并给出了机理 —— 三个执行器的限值来源不同（AFS 机械限、DB 摩擦限、MR 调制幅度），
它们之间没有一个可以线性表达的共享资源。

**顺带得到一个可写进论文的量化事实**：差动制动在两个工况下都只用到摩擦能力的
约 1/3，真正的绑定约束在别处（AFS 幅值限、LTR 包络、权重）。


### 2026-09-01 — 任务 #5：`Wdg` 迟滞，前提被推翻

**先把 `Wdg` 参数化**，不给裸数字。它的物理含义是**优先级的切换时间常数**：

γ 子问题 `min Nc·V·γ² + Wdg·(γ−γ_prev)²  s.t. γ ≥ γ_req`，
无约束最优 `γ* = Wdg·γ_prev/(Nc·V+Wdg)`，故每拍记忆保持率 = `Wdg/(Nc·V+Wdg)`。
令其等于 `exp(−Ts_exec/τ_γ)`：

```matlab
rho_g = exp(-Ts_exec / CostWeights.tau_gamma);
Wdg   = rho_g/(1-rho_g) * Nc * [V1 V2 V3];
```

`Wdg` 自动随 V 缩放，设计者只需给一个有物理意义的 `τ_γ`。

**然后前置检查推翻了任务前提。** 缺陷 C3 原文是「ρ_AFS 81% 时间贴边，

### 2026-09-05 — DLC 转角不平滑：查清了机理，但没有便宜的解（暂搁置）

**用户观察**：DLC 的前轮转角不平滑，车速掉、侧倾明显。

**核实**：转角有 **52% 的能量落在 1~3 Hz**（频谱峰在 1.28 / 1.44 / 1.76 Hz），
方向盘速率 RMS ≈ 360 deg/s（物理上限 720），17% 的时间顶在上限的 90% 以上。
**参考轨迹是光滑的**（控制器内部 `PrjP.yr` 的二阶差分 RMS 0.0009 m），
所以抖动是控制器自己产生的，不是规划或量测噪声。

**机理**：预测时域 `Np·Ts = 12×0.05 = 0.6 s`，
**短于闭环自己激起的振荡周期（1.3~1.8 Hz ⇒ 0.55~0.77 s）** ——
MPC 看不到自己动作一个周期之后的后果。

**试过的四条，全部记录**

| 手段 | 幅度 | 1~3Hz 能量 | ey_RMS | 结论 |
|---|---|---|---|---|
| `R1`（AFS 增量权重） | 1 → 3000 | — | 0.272→0.276 | **弱**：jerk 只降 18% |
| 加长 `Np` | 12 → 26（0.6→1.3 s） | 52%→**19%** | 0.272→**0.486** | **有效但摧毁跟踪**，制动占空 38%→90%，车速掉 6 km/h |

### 2026-09-05 — 任务 #7：松弛变量上界有限化

**原状**：`eps_ub = inf(Ne,1)`。设计意图是保证 QP 恒可行（配合 L1 精确罚，

### 2026-09-05 — B2 的核心问题：软约束不保证约束满足（已量化，部分可给出保证）

**问题陈述**（用户提出）：MPC 被构建为带松弛变量的软约束 QP。即使惩罚权重很大，
数学上也无法保证防侧翻、横向偏移、车道边界约束被严格满足。

**先分清两件事**（这决定该找哪类文献）：

- 软约束**保证有解** —— 这正是引入松弛的目的（松弛足够大总可行）；
- 软约束**不保证约束被满足** —— 这才是真正的缺口。

#### 文献给的答案：L1 精确罚

- **二次罚** `w·ε²`：梯度 `2wε` 在 `ε→0` 时趋零，故 `ε*>0` **恒成立**，
  与 w 多大无关。「权重再大也不保证满足」这句话对二次罚**成立**。
- **L1 精确罚** `w·ε`：梯度恒为 `w`。**精确罚定理**：只要 `w` 超过硬约束问题最优乘子的相应范数，则 `ε* = 0`
  **精确成立**，软约束解 **等于** 硬约束解（*前提是硬问题可行*）。

  **引用取舍**（2026-09-05 决定）：原始出处 Kerrigan & Maciejowski, UKACC 2000
  是会议论文且年代久远，**不作为主引**。改引：

  - **M. N. Zeilinger, M. Morari, C. N. Jones, "Soft Constrained Model Predictive
    Control With Robust Stability Guarantees," *IEEE Trans. Automatic Control*,
    vol. 59, no. 5, pp. 1190-1202, May 2014.** —— 正文明确陈述该性质：
    "when the weights on the l1 or l-inf norms are sufficiently large and there
    exists a feasible solution to the hard constrained problem, then the optimal
    solution to the soft constrained problem corresponds to the [hard] one"。
    TAC 期刊；且该文自身把 K&M 2000 列为参考文献 [6]，引它等于把源头一并带上。
  - 备选：A. Richards, "Fast model predictive control with soft constraints,"
    *European Journal of Control*, vol. 25, pp. 51-59, 2015.

本项目**已经在用 L1 精确罚**（`func_BuildQPCost` 的 `lambda_L1` / `w_L1`），
缺的是**验证条件是否真的成立**。

#### 可检验的判据

对 `ε_i` 在 0 处的稳定性条件：

```
w_L1(i)  >=  Σ_j λ_j        （j 遍历所有减去 ε_i 的约束行）
```

实现：`func_SolveMPCQP` 取 `quadprog` 的 `lambda.ineqlin`（列缩放不改变行的对偶变量，
故即原问题乘子），在 `cq32019mpc` 用 `Sind = -A_cons(:, eps列)` 求和比对。
脚本 `chk_exact.m`（需临时插桩，见文件头）。

#### 实测（DLC，621 拍，`lambda_L1 = 1`）

| 松弛项 | `w_L1` | max Σλ | 违反占比 | max\|ε*\| |
|---|---|---|---|---|
| **LTR±（防侧翻）** | 2e7 | **197.6** | **0%** | **9e-09** |
| 横摆角速度 r± | 6.875e5 | 1.227e6 | 5.15% / 4.35% | 0.343 rad/s |
| 侧偏角 α± | 6.875e5 | 7.333e5 | 9.82% / 8.53% | 0.029 rad |
| 车道边界 ey± | 7.5e6 | 8.346e6 | 7.09% / 7.41% | **0.451 m** |

#### 关键实验：加大权重是否有用？

把 `lambda_L1` 由 1 提到 5（权重 ×5）后：

| | w_L1 | max Σλ | 违反占比 | max\|ε*\| |
|---|---|---|---|---|
| r+ | 6.875e5 → 3.438e6 | 1.227e6 → **4.035e6** | 5.15% → 6.60% | 0.343 → 0.379 |
| ey− | 7.5e6 → 3.75e7 | 8.346e6 → **3.861e7** | 7.41% → 9.02% | 0.451 → **0.593** |
| LTR+ | 2e7 → 1e8 | 197.6 → 807.8 | 0% → 0% | ~0 |

**乘子随权重同步增长，违反占比不降反升。** 这是**硬约束问题本身不可行**的特征 ——
若硬问题可行，`λ*` 是硬问题的固有属性、与软罚权重无关，加大 w 必然使条件成立。
乘子跟着涨，说明那些时刻**横摆包络、侧偏包络、车道边界三者无法同时满足**。
Kerrigan & Maciejowski 的定理本就带前提「*whenever the hard problem is feasible*」。

`lambda_L1` 退回 1.0（提到 5 反而使最大越界从 0.451 增至 0.593 m）。

#### 结论（可直接写进论文）

1. **防侧翻约束有数学保证**：精确罚条件在 621 拍中 **100% 成立**，
   乘子上界 197.6 对权重 2e7，裕度五个数量级，`ε* ≈ 9e-9`。
   由 Kerrigan & Maciejowski 的定理，此时软约束解**等于**硬约束解，
   即 LTR 约束被**严格满足**。这不是"权重够大"的经验陈述，是可检验的条件。
2. **横摆/侧偏/车道边界无法保证，且无法通过加大权重获得**：
   实测证明这些时刻硬问题不可行。此时 `ε*>0` 是设计意图内的**优雅降级**，
   其量值有界且已量化（最大越界 0.451 m，占比 4~10%）。
   这比"无法保证"是更强、也更诚实的陈述。

物理上就无法把 |LTR| 压在 0.8 以内**。鱼钩本来就是为诱发抬轮而设计的工况。

##### 对论文叙事的修正

不能写"防侧翻约束有数学保证"（那只对 DLC 成立）。改写成：

1. 采用 L1 精确罚，给出**可逐拍检验的充分条件** `w_i >= sum_j lambda_j`；
2. **DLC：条件 100% 成立**（裕度 5 个数量级）=> 软解 = 硬解，LTR 严格满足；
3. **鱼钩：条件不成立**，且经两组实验证明是**硬问题真不可行**，
   任何有限权重都无效；此时 `eps* > 0` 是有界、可报告的优雅降级
   （预测 |LTR| 峰值 1.075；实测抬轮 2.81%，对照 baseline 10.62%）。

**这个判据本身就是贡献**：它能区分"控制器没调好"与"工况超出车辆物理能力"，
并在前一种情形下给出证书。比笼统声称"权重够大就行"强得多。

##### 代码变更

- `func_BuildQPCost.m`：`w_L1 = lambda_L1(:) .* (Np*diag(W).*eps_scale)` ——
  允许 `lambda_L1` 为 Ne x 1 向量逐项设定（标量时与原式完全等价，无行为变化）。
- `lambda_L1` 仍为 1.0。插桩（`QPLAM` / `EXACTDBG`）已全部移除。
- 新增脚本：`sweep_ltr.m`、`ltr_solo.m`（均需插桩，见 `chk_exact.m` 文件头）。

#### 关于"能不能顺带保证稳定性"（2026-09-05 逐篇核查原文）

**结论：CBF 那一支保证不了；Zeilinger 2014 那一支能保证，但本项目用不上。**

| 文献 | 保证什么 | 不保证什么 |
|---|---|---|
| **Zeng, Zhang & Sreenath (ACC 2021)**<br>MPC-CBF, arXiv:2007.11718 | 安全集前向不变（**前提是每拍 QP 可解**） | **全文 0 条 Theorem，只有 8 条 Remark**。<br>Remark 4 原文：*"for a given fixed gamma, we generally only have **pointwise feasibility** and a **persistently feasible formulation is still an open problem** and is part of future work."*<br>稳定性一节原文：*"a rigorous proof of nonlinear MPC stability as well as MPC-CBF **still remains an open challenge**."*<br>Remark 3 又指出 gamma 小则更安全但**更容易不可行** |
| **Zeilinger, Morari & Jones (TAC 2014)** | **Theorem IV.3** 所有可行参考稳态渐近稳定；<br>**Theorem V.2** 加性扰动下 ISS；<br>大范围可行性 + 精确罚（可行时软解=硬解） | 要求 **LTI 且 (A,B) 可镇定**（Assumption II.1）；<br>tracking 形式（人工稳态）；<br>需离线终端 PI 集 + 条件 A3/A4（A4 比不变性更强；K 取 LQR 时 T 由 DARE 给出）；<br>需 xi>0；问题变成 **SOCP** 而非 QP |

**对本项目的可迁移性**：本文模型是**逐拍重线性化的 LTV**（轮胎切线刚度每拍变），
且是**分层结构**（上层 MPC 出广义力 + 下层 QP 分配）。Zeilinger 的 LTI 假设、
终端不变集、DARE 终端权均不成立，硬套需重做整个架构。

**更重要的是：审稿人问的是"约束满足"，不是"闭环稳定"。**
不要把靶子从可以打中的（LTR 约束满足，已实测验证）挪到打不中的（Lyapunov 稳定性）。
若引 MPC-CBF 作为"解决方案"，反而会被指出该文自己承认递归可行性与稳定性都是 open problem。

#### 若要更强的"构造级"保证（未做，工作量大）

文献路线：

- **控制不变集 / 终端集**：把终端约束设为控制不变集，可得递归可行性；
- **控制障碍函数 (CBF)**：MPC-CBF 保证安全集的前向不变性
  （Zeng et al., *Safety-Critical MPC with Discrete-Time CBF*, arXiv:2007.11718；
  *Predictive Control Barrier Functions*, arXiv:2502.08400）；
- 车辆侧翻方向的直接先例：*Rollover Prevention for Mobile Robots with
  Control Barrier Functions*, arXiv:2403.08916。

这类方法能把"条件成立时保证"升级为"构造上保证"，但需要离线计算不变集，
且对时变模型（本项目 A、B 每拍变化）要做鲁棒化处理。

## 2026-09-05  纵向前馈限速 Vxmax（已实装 + 实测）

依据《鱼钩工况Vxmax纵向前馈控制方案.md》实现。

### 公式（按 §4 文献推导）

- **侧翻项** —— Yang et al., IEEE TVT 2022, Eq.(56)(57)，平路 th=0：
  `a_y,th = g*(Tw/2) / (h_cgs + h_s*R_phi)` ,  `R_phi = ms*g*h_s/(k_phi - ms*g*h_s)`
- **摩擦圆** —— Abe, *Vehicle Handling Dynamics* 2015, Eq.(2.42)：
  `a_y,fric = sqrt((mu*g)^2 - a_x^2)`
- `a_y,lim = min(LTR_gov*a_y,th , a_y,fric)`
- `v_x,max(k) = min_{i=0..Np} a_y,lim/|psi_dot(k+i|k)|` （预测序列取最小）
- `v_x,ref = min(v_tar, v_x,max)` → `sys(32)` → 已有的 `PID velocity control`

### 三条独立推导的交叉验证（a_y @ LTR=1）

| 推导 | 值 |
|---|---|
| Yang 2022 Eq.(56)(57) | **0.8236 g** |
| 本项目 LTR 模型 `k_LTR = 0.11418` | 0.8931 g |
| 纯 SSF（无侧倾柔度） | 0.8829 g |

相差 < 8.4%，互相印证。

### 实测 A/B（鱼钩，入弯 80 km/h）

| | Gov OFF | Gov ON |
|---|---|---|
| 末速 / 最低速 | 77.7 / 75.6 km/h | **43.8 / 36.7 km/h** |
| 全程 \|LTR\| 峰 | 0.9564 | **0.9845** ↑ |
| 侧倾峰 | 4.602° | **5.354°** ↑ |
| 瞬态段 (t<2.5) \|LTR\| 峰 | 0.9564 | 0.9845 ↑ |
| 准稳态 (t>2.5) \|LTR\| 峰 | 0.8466 | 0.8491 |
| 准稳态 \|LTR\| 均值 | 0.7649 | 0.7494 |

**车速降了 35 km/h，LTR 几乎不变。**

### 为什么无效：轮胎饱和后 a_y 与 v_x 解耦

固定转角 delta 下：`a_y = V^2*delta/(L + K_us*V^2)`。
当 `K_us*V^2 >> L`（轮胎进入饱和）时 `a_y -> delta/K_us`，**与 V 无关**；
此时 a_y 被附着夹死在 `mu*g`，降速只会让 `psi_dot = a_y/V` **上升**。

实测印证：`|r|` 峰值从 **0.578 → 0.662 rad/s**（降速后反而变大）。
于是限速器自我正反馈：V↓ → r↑ → `V_max = a_y,lim/r` ↓ → 一直滑到 30 km/h 下限，
低速段限速持续激活占比 **96.9%**。

### 减速能力：是被摩擦圆卡死，不是通路不行

| | |
|---|---|
| 实测 a_x 峰 | 4.310 m/s² = **0.439 g** |
| 达到摩擦圆余量的95% 以上的时间 | **31.8%** |
| 从限速触发(t=0.26, 78.6 km/h)到 LTR 峰(t=1.91) 需要 | **0.803 g** |
| 该窗口内摩擦圆平均只能给 | **0.282 g** |

差一个量级。早前怀疑的"PID 被差动制动门控关断"**不成立**。

### 附带发现

- `a_y = v_x*psi_dot` 仅在 `beta_dot ≈ 0` 时成立。鱼钩中 `V*r` 峰值达 **1.261 g**，
  而真实 a_y 不可能超 `mu*g = 0.78 g` —— 公式偏保守达 60%，这也是限速长期满载的原因之一。
- CarSim 导出的 `Ax`(u47) / `Ay`(u48) **恒为 0**，`VehStateMeasured.Ay` 一直是死信号；
  `u(62)` 是 CarSim 自己的 LTR，可作真值。
- 鱼钩入弯速度是 **80 km/h**（`VxTarget` 恒定），不是 100。

### 结论

**Vxmax 前馈在"曲率被参考路径固定"的工况（DLC）上成立，
在"固定转角 + 轮胎饱和"的鱼钩上结构性失效。**
鱼钩的侧翻裕度只能来自"同一 a_y 下降低 LTR"（MR 悬架 + AFS，即现有方案已做的）
或车辆设计（h_cg、轮距），而不是速度。

- 新增：`gov_eval.m`、`gov_report.m`、`gov_ab.m`、`gov_fric.m`、`gov_ts.m`。
- `GOVDBG` 插桩仍在 `cq32019mpc.m`（标记 `%<<<GOVDBG` / `%>>>GOVDBG`）。

## 2026-09-05  横纵向耦合: 约束触发式纵向减速（DLC，已定型）

### 重要更正: 之前所有手算用错了车辆配置

`PMPC_cargo = wsget('PMPC_CARGO', 0)` 默认 **0（空载）**，而分析时用的是
`func_VehicleParams(1)`（载货）。真实参数：

| | 误用(载货) | **实际(空载)** |
|---|---|---|
| m | 2030 | **1860** |
| ms | 1760 | **1590** |
| h_SL | 0.892 | **0.72** |
| h_S2R | 0.742 | **0.57** |

**结论翻转**：a_y,th 从 0.824 g 变为 **1.045 g** > mu_eff*g = 0.78 g。
即该车（空载、mu=0.9）**附着先到、不是侧翻先到**，
之前写的"侧翻受限而非附着受限"**作废**。
`Constraints.ay_bar = min(0.8*ay_th, mu_eff*g) = 7.649`（取附着值）。

**同时作废**：鱼钩 LTR-vs-车速"断崖"表（0.826->0.638），需用空载参数重算。
（代码里 ay_bar 是自动算的，所以**仿真结果本身有效**，只有手算叙事错了。）

### 最终机制

- **触发**：预测轨迹 `Y` 中的 |ey| 在预测时域内超过 `beta*emax`，或 LTR 松弛 > 0。
  （beta=1.0 与“eps>0”等价，已实测逐位吐合）
- **减速量**：由速度误差生成，受**摩擦菱形**限幅
  `ax_avail = ax_bar*(1 - |a_y|/ay_bar)`（Wischnewski 2023 Eq.10a）。
- **执行**：进 `func_QPA_DB` 同一个分配 QP，横摆力矩优先（`Gov_lamx=0.5`）。
  **不能走 CarSim 自带的纵向 PID** —— 它的制动通道 `IMP_PCON_BK`
  接的是常数 0，只有油门没有刹车（实测滑行减速仅 0.07 g）。
- **`fx_aware`**：把制动力按摩擦椭圆从横向上界扣除
  `Flim = 0.95*sqrt((mu_eff*Fzf)^2 - Fx_f^2)`（Abe Eq.2.42）。

### 实测拆解（DLC 100 km/h）

| 配置 | \|ey\| RMS | \|ey\| 峰 | >emax % | 平均车速 |
|---|---|---|---|---|
| 全关（基准） | 0.2639 | 0.6863 | 7.085% | 98.60 |
| 仅 fx_aware | 0.2658 | 0.7097 | 7.235% | 98.56 |
| 仅 eps 减速 | 0.2687 | 0.7092 | 7.870% | 94.65 |
| **两者都开** | 0.2789 | **0.6268** | **4.916%** | 94.13 |

**两个单独都是负收益，只有合起来才有效。**
机理：只减速会偷走横向附着而 MPC 不知情 -> 超发；
只 fx_aware 则 MPC 变保守却无手段降低需求；
两者共存时供需对上。代价是 RMS +5.7%（峰值/越界换均值）。

### 否定的方向（均有实测）

1. **收紧触发门限 beta<1**：beta 1.0->0.85 使越界从 4.9% **翻倍到 11.1%**，
   车速还掉 15 km/h。因为 0.6 s 预测时域够不到换道段之外，提前只意味着
   在换道**过程中**更频繁地刹（激活率 14.6%->31%->50%），抢横向附着。
2. **路径预瞄前馈限速（`Gov_pv` + `func_SpeedProfile`）**：
   即使 margin 降到 0.45（平均车速 90 km/h），越界只降 2.4%。
   原因：**|ey| 是几何决定的，不是横向能力决定的**——中心线 100 km/h 要 2.81 g，
   90 km/h 还要 2.28 g，仍是能力的 3 倍，车照样走走廊线。
   要靠降速消掉得降到 ~53 km/h。代码保留，`Gov_pv=0`。
3. （鱼钩）不启用——固定转角 + 轮胎饱和下降速无效且会变差，已实测两次。

## 2026-09-12  DLC 改为 Add 模式：架构自洽，拖动问题随之解决

### 起因

用户在 CarSim I/O Channels 里把 `IMP_STEER_SW` 从 **Replace** 改成 **Add**。
核实：DLC Run 本来就启用了闭环驾驶员
（`Control: Steering by the Closed-loop Driver Model / Double Lane Change (Quick Start)`，
`AV_SW_MAX_DM 1200`、`TLAG_DM 0`），所以 Add 是真正生效的。

**关键核实**：CarSim 驾驶员的 `LTARG_TABLE` 与本项目 `func_WayPoints(1)` 是**同一条路径**：

| X | CarSim LTARG | 本项目 waypoints |
|---|---|---|
| 80 | 1.8 | 1.763 |
| 90 | 3.4 | 3.363 |
| 130 | 2.4 | 2.44 |
| 140 | 0.2 | 0.258 |

故不会互相对抗。

### 算法改动（四处，均为"把 DLC 对齐到鱼钩的 Add 逻辑"）

1. `delta_robot`：取消工况分支，统一为 `delta_f - InitialParams.U(1)`
   （原 DLC 写死 0，那是 Replace 下"控制器即驾驶员"的假设）
2. AFS 输出：两个工况都**只发增量** `func_AFS(..., Fyf_next)`；

## 2026-09-12  执行器抖振: R 矩阵无效, 病根在分配 QP

### 现象
Scope 上 ② ZENG 的四个轮缸力矩逐拍乱跳。量化(对时间求导的 RMS):

| | ① MPC | ② ZENG | ③ PMPC |
|---|---|---|---|
| dTb RMS (N·m/s) | 1378 | **2335** | 554 |
| dFd RMS (N/s) | 3292 | 3085 | 3323 |

即**只有制动通道、且只有 ZENG 特别抖**; MR 通道三者相当。

### R 矩阵全试过, 对 dTb 无效
| R2 | 1e1 | 3e1 | 1e2 | 3e2 | 1e3 |
|---|---|---|---|---|---|
| dTb RMS | 2335 | 2384 | 2419 | 2254 | 2370 |
| \|r\|>μg/Vx % | 10.0 | 10.6 | 9.4 | 6.9 | 5.6 |
| 尾段\|SW\|峰 | 15.9 | 40.0 | 20.9 | 28.7 | 30.8 |

R1(1/3/10)、R3(5/50/500/5e3) 同样对 dTb 无效; R3 能压 dFd(3085->1695)
但侧倾峰 1.605->2.200、\|LTR\| 0.417->0.494, 不划算。

**原因**: R1/R2/R3 罚的是**上层 MPC** 的 Δu(广义力), 而抖振产生在**下层分配 QP**。

### 病根: 分配 QP 秩亏而正则项形同虚设
`func_QPA_DB` 里 `H = 2*(Bb'*Bb + rho*Gamma_u)`:
- `Bb'*Bb` 是**秩 1**(4 个轮缸力矩、只有一个横摆目标), 解在 3 维零空间里不唯一;
- `Gamma_u = diag((1./(rt*mu*Fz)).^2) ~ 1.6e-6`, `rho=0.1` => 正则项 ~1.6e-7,
  而 `Bb'*Bb ~ 5.1` —— **小七个数量级, 等于没有**。

于是逐拍由 active-set 的搜索路径随机挑一个等价解, 轮缸力矩就乱跳。

**这个洞 MR 那路早就补过**: `func_QPA_CDC` 有 `rho_c=0.05` 的增量惩罚,
注释里写的诊断("Bd*Fd=MFd 有 3 维零空间...active-set 在这些等价解间跳动
就是阻尼力高频抖动的来源")与此处一字不差 —— 当时**漏了制动路**。

### 修法: 给制动分配器补同一项
```matlab
T_ref = max(rt*mu*Fz_tot/4, 1);   % N*m, 单轮制动力矩能力
M_ref = max(mu*Fz_tot*tf/4,  1);  % N*m, 差动制动横摆能力
kd    = Constraints.QPA_lamd * (M_ref/T_ref)^2;
H = H + 2*kd*eye(4);   f = f - 2*kd*Tb_prev;
```
归一化沿用本文件约定: `lam_d=1` <=> 「用满单轮力矩能力的增量」与
「用满差动制动横摆能力的残差」同价; `<1` => 横摆优先。与 `Gov_lamx` 同一套量纲。

**锚点**(非纯经验): MR 那边 `rho_c/||Bd'Bd|| = 0.05/0.30 = 0.17`;
制动这边 `||Bb'Bb||=5.1`、`(M_ref/T_ref)^2=20.4`, 同比例即 `lam_d ~ 0.04`。

### lam_d 扫描 (ZENG, R2=1e1)

|---|---|---|---|---|---|---|---|---|

| 尾段\|SW\|峰 | 15.9 | **13.1** | 15.7 | 21.6 | 20.2 | 13.4 | 24.6 | 24.0 |

`lam_d=0` 与改动前 **MD5 逐字节相同**(零回归已验证)。
`lam_d` 越大抖振越小但 \|r\| 超限单调变差 —— 后者是 ZENG 的立身指标。

## 2026-09-12  ZENG 为什么慢 8 km/h: 根因是原文的稳态近似

### 出发点
② ZENG 平均车速 68.96 km/h, 而 ① 78.25 / ③ 78.86。要少降一点。

### 先排除实现问题
1. **`Vset_zg` 确实接进了 CarSim 的速度 PID 目标**(不是只记录):
   油门呈 0/1 砰砰跳而非稳定补速 —— t=1.6 s 时车速 75.6 km/h 却油门 0
   (限速目标已降到 ~64), t=3.6/6.8 s 限速一放开立刻油门到底。
   => 降速是**被指令出来的**, 不是被差动制动拖的。
2. **预测确实有高估, 但只占一小部分**。插桩比对"预测 horizon-max"与
   "实际未来 0.6 s 内真实最大 |r|": 均值高估 **1.24 倍**, 62% 的拍高估>5%,
   90 分位 2.04 倍; 预测峰 0.90 rad/s 而实测 |r| 全程不超 0.3225。
   t=2.41/4.41 s 两处把 Vset 砸到 38/40 km/h。

### 试过的三种放松, 都只值 1~2 km/h
| 方案 | 车速 | ey RMS | \|r\|超限% |
|---|---|---|---|
| 基准(horizon-max) | 68.96 | 0.1992 | 6.9 |
| 可达性折扣 apv=1 (V(k)<=min_i[μg/r_i + a_brk·iTs]) | 69.86 | 0.2042 | 10.6 |
| 预瞄窗口 Npv=8 (0.4 s) | 71.08 | 0.2105 | 12.5 |
| **物理可达性剪切 kovs=1.3** | **70.43** | 0.2065 | 10.0 |

- 可达性折扣没用, 因为 `a_brk = ax_av = ax_bar(1-|ay|/ay_bar)` 在限速真正
  起作用时(横向吃满)本来就 ≈ 0, 折扣项自动归零。物理自洽, 但没余量可放。
- 缩窗口是拆东墙补西墙: +2.1 km/h 换 ey +5.7%、\|r\|超限翻倍。
- **kovs 剪切是唯一"白拿"的**: 预测峰 0.90 rad/s 在 Vx=17 m/s 下等于
  a_y=1.56 g, 在 μ=0.5 上**根本不可能发生**, 是线性化模型的外推失真。
  按轮胎实际能力剪: `r <= kovs*mu_eff*g/Vx`, kovs=1.3 取自实测超调
  (实测 \|r\|峰 0.3225 / 当时 mu_eff*g/Vx=0.251 = 1.28)。
  **+1.5 km/h, 且尾段\|SW\|峰 13.1->7.5 反而更好。**

### 真正的根因: `a_y ≈ Vx*r` 这个稳态近似

| | Vx·r 峰 | **真实 Ay 峰** | 保守度 | Vx·r>μg 占比 |
|---|---|---|---|---|
| ① MPC | 0.670 g | **0.423 g** | 1.58x | 28.7% |
| ② ZENG | 0.693 g | **0.415 g** | 1.67x | 10.0% |
| ③ PMPC | 0.772 g | **0.423 g** | 1.83x | 35.3% |

**三者真实侧向加速度峰值都是 0.42 g, 正好顶在轮胎能力 0.4275 g 上, 谁都没超
附着极限。** 原文 Eq.(26e) 的 \|r\|<=μg/Vx 是从 `a_y <= μg` 代入稳态近似
`a_y ≈ Vx*r` 得来的; 在换道瞬态里 dVy 与 Vx*r 反号, 该近似比真实 a_y
**严 1.6~1.8 倍**。ZENG 让出的 ~8 km/h 全数来自这个近似误差。

### 把近似换成完整式 a_y = dVy + Vx*r (Zg_ayfull=1, 物理约束一字未改)
修正因子 `c = |Vx*r| / |a_y|`, 上限 `Zg_cmax`:

| c 上限 | 1.0(原文) | 1.15 | 1.3 | 1.5 | 3.0(全) |
|---|---|---|---|---|---|
| 平均车速 | 70.43 | **77.54** | 77.49 | 78.25 | 78.25 |
| ey RMS | **0.2065** | 0.2510 | 0.3025 | 0.3067 | 0.3070 |
| 越界 % | **0** | 1.26 | 7.55 | 8.28 | 8.28 |
| \|r\|超限 % | **10.0** | 18.9 | 33.3 | 27.4 | 27.4 |
| 尾段\|SW\|峰 | 7.5 | 6.8 | 90.3 | 59.6 | 59.3 |

车速能全数拿回, 但**跟踪精度就是靠降速换来的**: c=3 时 ey 0.3070,
比 ① MPC 的 0.2379 还差(因为 ZENG 还背着更紧的鞍点 α_r 界和 ρ 调权,
没有降速兜底就吃亏)。

### 决定 (2026-09-12, 用户拍板)
**保持 `Zg_ayfull = 0` 忠实复现原文**, 只收下 kovs 剪切的 +1.5 km/h。
车速 70.43 km/h。论文叙事: ZENG 用 8 km/h 换来三者最好的 ey(0.2065)、
最好的 \|LTR\|(0.4050)、0 越界、\|r\|超限仅 10%; 而 PMPC 在 78.86 km/h

## 2026-09-12  油门 0/1 砼砼跳 + 发现 ERD **截断**

### 一、油门砼砼跳的成因
把 `cq3_2019.slx` 解包查接线(slx 就是 zip, `simulink/systems/*.xml`):
- S-function 输出第 **31** 路 = `Vel*3.6` -> PID 的 `Vx`;
  第 **32** 路 = `Vset_zg` -> PID 的 `Set_Vx`; 第 18 路 = `MFx_next` -> `DB_active`。
  => 确认限速值就是 CarSim 速度 PID 的设定值。
- PID (`system_1502.xml`): **Kp=0.1, Ki=0.005, 输出饱和 [0,1], 无制动通道**
  => 比例带只有 **10 km/h**。而 `Vset_zg` 在 38~80 km/h 之间跳,
  油门必然在 0/1 之间砼砼响。

### 修法: 只滤 PID 那一路
这条链路上混了两件事:
- **约束执行** = `Fx_dem` 差动制动, 必须即时响应;
- **速度跟随** = CarSim 的 PID, 本质是驾驶员/动力系统模型, 带宽有限。

所以给输出第 32 路换成一阶滞后的 `Vset_pid` (时间常数 `Zg_tpid`),
而 `Fx_dem` 仍用**未滤波**的 `Vx_lim` —— 制动响应一点不延迟, 忠实度不受影响。

### 二、顺藤摸瓜查出 ERD **截断** (重要)
同一组参数两次跑出 160 拍和 173 拍, 而前 160 拍**逐字节相同**——

- 停机条件是**站点**: `LastRun_log.txt` 写 "Run stopped at t = 8.751.
  Station limit reached: driver station = 200.002"。车越慢跑得越久、采样越多,
  所以**只有最慢的 ZENG 被截断**(MPC 157 拍 / PMPC 156 拍 从未受影响)。
- 旧判据 "文件大小稳定 0.25 s" 不可靠: CarSim 分块刷盘, 块间停顿可能
  超过判稳窗口。

**新判据** (`func_WaitERD.m`): 等 `LastRun_log.txt` 被重写且出现
